# Plan: existencias reales, edición de catálogo e informe de importación

## Diagnóstico (lo que explica cada síntoma)

| Síntoma | Causa raíz |
|---|---|
| Se escogen componentes sin existencias | El picker solo bloquea `cd_only_best` (`src/views/assembly.ts:110`); `stock_ensamble_total` se muestra pero no se aplica; `+` no tiene tope; "Usar este" ignora `o.stock_ensamble`; `set_assembly_item` (backend y mock) no valida stock. Además la lista de componentes queda **stale** tras importar: `settings.onChanged → refreshOverview` no recarga componentes (`src/main.ts:122,136`). |
| No se puede editar un componente | No existe ningún comando `update_*` en backend ni UI; el form es solo alta; `store.rs:556` dice "edítalo desde el catálogo" pero no hay tal cosa. |
| Gabinete con fuente no reconocido | `includes_psu`/`psu_watts` viven en `products.specs` JSON y se infieren del texto "CON/SIN FUENTE" (`suppliers.rs:629-643`); el import de arroba **sobrescribe `specs` completo** (`db.rs:604`), así que cualquier corrección manual se pierde. |
| Preensambles "no se actualizan" | Los ensambles ya resuelven precio/stock en vivo (sin snapshot), pero la UI no recarga tras el import. Renombrar ya existe (`assembly.ts:621`) — no se toca. |
| Sin informe post-import | `import_catalog_xlsx` devuelve solo `{updated, inserted, total, supplier}`. |
| SKU ausente del XLSX conserva stock viejo | `apply_import` (`store.rs:225-275`) solo itera los SKUs entrantes; no hay barrido. |

## Decisiones (confirmadas contigo)
- Componente sin existencia en ensamble vigente → **Error** de validación (bloquea confirmar y nota de venta).
- SKU ausente del XLSX de arroba/cva → **conservar oferta con existencia 0** (último precio conocido, no seleccionable).
- Renombrar: ya existe, sin cambios.

## Cambios

### Backend (Rust, `src-tauri/src`)

**1. `db.rs` — migración v8 + overrides + barrido**
- Migración v8: `ALTER TABLE products ADD COLUMN overrides TEXT NOT NULL DEFAULT '{}'` (JSON `{ "kind"?: string, "specs"?: {…} }`). El import **nunca** toca esta columna.
- `load_products`: leer `overrides`, calcular efectivo: `kind = overrides.kind ?? kind`, `specs = specs ⊕ overrides.specs` (override gana clave por clave). Exponer `overrides` en `Component` para que la UI muestre candado.
- Nueva `update_master_manual(conn, id, description, brand, condition, kind, specs)`: actualiza descripción/marca/condición directo; para `kind` y `specs` calcula el **diff contra lo que vino de la lista** (`products.kind`, `products.specs`) y guarda solo las claves distintas en `overrides` (si el usuario deja un valor igual al de la lista, no se bloquea). Así "incluye fuente" marcado a mano sobrevive a todos los imports futuros.
- Nueva `update_offer_manual(conn, sku, supplier, price, currency, stock)`: solo para ofertas `manual`/`pch` (precio + almacén `pch_existencia`/`manual`).
- Nueva `zero_absent_offer_stock(conn, supplier, present_skus)`: `DELETE FROM offer_stock` del proveedor para SKUs no presentes (la fila de `product_offers` se conserva).

**2. `store.rs`**
- `apply_import`: envolver en transacción (`unchecked_transaction`) para no dejar estado parcial; recibir `supplier`; si es `arroba` o `cva` y el archivo trajo ≥1 producto, ejecutar el barrido tras los upserts.
- `import_xlsx_catalog`: **snapshot antes / comparación después**. Antes: recolectar ítems de ensambles con `status(hoy) != Caducada` con su `stock_ensamble` disponible (oferta fijada si `item.supplier` es `Some`, si no el total). Después de recargar catálogo: por cada ítem con `disponible < quantity` generar `OutOfStockHit { component_id, sku, description, kind, stock_after, newly_out (antes sí alcanzaba), assemblies: [{id, name, quote_type, quote_number, quantity}] }`. Devolver `(updated, inserted, supplier, hits)`.
- Nuevo `update_component(id, input)`: valida que exista; aplica `update_master_manual`; si `input.price/stock` vienen, exige que el proveedor indicado sea `manual`/`pch` (si no, error "el precio/existencia de lista no se edita, se actualiza con el Excel"); recarga catálogo.
- `set_assembly_item`: antes de `set_quantity`, rechazar si `quantity > disponible` salvo que sea reducción (`quantity <= cantidad actual`) o `quantity == 0`. Mensaje: `Sin existencia para ensamble: {sku} (disponible {n})`.
- `record_sale_note`: si hay `assembly_id`, además de Caducada rechazar si `validate(...).is_valid == false` (listar issues).

**3. `domain/assembly.rs` — `validate()`**
- Nuevo issue **Error** `out_of_stock` por ítem con `quantity > stock_ensamble` (oferta fijada o total): "Sin existencia para ensamble: {desc} (pedido {q}, disponible {n})". Esto hace `is_valid=false` → confirmar bloqueado, `missing_count` lo cuenta y el slot lo pinta en rojo.

**4. `domain/component.rs`** — campo `overrides: Overrides { kind: Option<ComponentKind>, specs: Specs }` en `Component` (serde default).

**5. `commands.rs` + `lib.rs`** — comando `update_component(id, input: UpdateComponentInput)`; `XlsxImportSummary` gana `out_of_stock: Vec<OutOfStockHit>`; registrar en `generate_handler!`.

**6. `catalog/mod.rs`** — `UpdateComponentInput { description, brand, kind, condition, specs, supplier?, price_amount?, price_currency?, stock? }`.
